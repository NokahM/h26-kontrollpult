Språket

JavaScript er en implementasjon av standarden ECMAScript. Språket er ikke Java, selv om syntaksen ligner. Det kjører både i nettleseren (klientside) og på tjeneren (for eksempel node). Prøv kodebitene i nettleserens konsoll (F12 → Console) eller med node.

Dynamiske typer og typekonvertering

Typen bestemmes ved tilordning, ikke ved deklarasjon. + skjøter tekst så snart en av operandene er tekst, mens -, * og / alltid prøver å gjøre om til tall:

// dyn_var.js
var a, b
a = 1 + '2'      // '12'  (tekst)
b = 1 +  2       // 3     (tall)
console.log(a, b)   // 12 3

Primitiver og objekter

Det finnes tre grunnleggende primitiver: boolean, number (alltid 64-bits flyttall) og string. Alt annet er objekter. Kaller du en metode på en primitiv, lages et midlertidig objekt som forsvinner rett etterpå:

a = 1
a.toString()        // virker: midlertidig Number-objekt
s = "tekst"
s.b = "bla bla"     // lagres på et midlertidig objekt ...
s.b                 // ... som er borte: undefined

null betyr «uten verdi». undefined er verdien til en variabel som ikke er initialisert, eller et medlem som ikke finnes. NaN er ikke lik noe, heller ikke seg selv, så test med isNaN().

Objekter og tabeller

Et objekt er en mengde navn-verdi-par, en hashtabell. Objektlitteralen er opphavet til JSON:

o = { navn: 'per', nummer: 123 }
o["navn"]            // 'per'
o.navn               // samme medlem
o.etternavn = "Hansen"   // nytt medlem

En tabell (array) er også et objekt, men ordnet og med length, som alltid er én større enn den største heltallsnøkkelen. diverse.js fyller et objekt, en hashtabell og en tabell med de samme nøklene og skriver dem ut. Bare tabellen har length (3). For de to andre er den undefined.

Funksjoner, this og gyldighetsområde

Funksjoner er objekter og kan defineres som uttrykk (var f = function (x) {…}), som setning (function f(x) {…}) eller som pilfunksjon (x => …). Alle returnerer en verdi, som er undefined hvis ingenting annet er angitt. this er objektet funksjonen ble kalt som metode på.

Variabler deklarert med var har funksjonsskop, ikke blokkskop, og deklarasjonen heises (hoisting) til toppen av funksjonen. Tilordner du til en variabel som ikke er deklarert noe sted, havner den i det globale objektet. Det er poenget med scope.js:

// scope.js (uten #!-linja)
print = console.log
v = "X"                    // global
var o = new Object()
o.v = "Y"                  // medlem av o
o.f = function () {
    v = "Z"
    print(global.v)
    print(this.v)
    print(v)
    var v                  // kommenter bort denne, observer og forklar
}
o.f()
Hva skrives ut, med og uten var v?

Med var v: deklarasjonen heises til toppen av f, så v = "Z" skriver til en lokal variabel. Utskriften blir X, Y, Z.

Uten: det finnes ingen lokal v, så v = "Z" overskriver den globale. Utskriften blir Z, Y, Z.

this.v er Y i begge tilfeller, fordi f kalles som metode på o. (Kontrollert med node.)

Hva blir utskriften fra tabelleksempelet i notatene? 
var a = []
a[04] = 'start'
a[09] = 'slutt'
console.log(a.length)      // 10: største indeks er 9
t1 = [,,]                  // length 2: avsluttende komma teller ikke
t1[2] = 'tredje element'
console.log(t1)            // [ <2 empty items>, 'tredje element' ]

04 og 09 er bare 4 og 9 her. Ledende null betyr egentlig oktalt, men 09 er ikke et gyldig oktaltall og leses derfor som desimalt. I streng modus ("use strict") er begge syntaksfeil. (Kontrollert med node.)

Resten av grunnspråket ligner på C og Java: if/else, while, for, switch og try/catch/finally. Unntaket er for (x in X), som går gjennom nøklene i et objekt.

JavaScript i nettleseren

Nettleseren representerer dokumentet som et tre av noder, DOM (Document Object Model). DOM er en W3C-standard og ikke en del av ECMAScript. Det globale objektet heter window, ett per vindu eller fane, og alle globale variabler er medlemmer av det.

Hendelsesbehandlere

I DOM nivå 0 er behandleren en attributtverdi eller en egenskap (onload = f). Da kan det bare være én behandler per hendelse. Fra DOM nivå 2 brukes addEventListener. Behandleren får et hendelsesobjekt med detaljer, og hendelsen «bobler» oppover i treet til noen kaller stopPropagation():

// musealarm2.html (forenklet)
function musealarm(hendelse) {
  alert('Du trykket musknapp nr. ' + hendelse.button)
}
function initialisering() {
  document.querySelector('#musefelle')
    .addEventListener('mousedown', musealarm, false)
}
window.addEventListener('load', initialisering, false)

musealarm1.html gjør det samme, men registrerer initialisering med <body onload=…>. Begge venter til #musefelle finnes før de slår opp elementet.

Finne og endre elementer

document.querySelector('#epost')          // første treff på en CSS-velger
document.querySelectorAll('a')            // alle treff
document.getElementById('epost')          // eldre, virker fortsatt

let e = document.createElement('a')       // ny elementnode

e.className = 'aktiv'                     // class er reservert ord

Det er nesten bare querySelector(…).value eksamenskoden bruker. Den leser verdien i et <input>-felt før den sendes med fetch().

Web-applikasjoner: AJAX og fetch

AJAX betyr at siden gjør HTTP-forespørsler fra JavaScript uten å laste hele siden på nytt. Det eldste API-et er XMLHttpRequest:

// ajax_get.html (forenklet)
var f = new XMLHttpRequest()
f.open("GET", "sql-klient3.cgi?" + s, true)   // true = asynkron
f.onload = function () {
  document.getElementById("tabell").innerHTML = f.responseText
}
f.send(null)

readyState går fra 0 (UNSENT) via 1 (OPENED), 2 (HEADERS_RECEIVED) og 3 (LOADING) til 4 (DONE). status er HTTP-statuskoden.

Fallgruve: sql-klient3.cgi er SQL-injeksjon med vilje

Skriptet sender spørrestrengen rett til sqlite3. Den som skriver i feltet, kan kjøre hvilken som helst SQL, også DROP TABLE. Eksempelet viser AJAX, ikke hvordan en tjeneste skal lages. Se forberedte SQL-kommandoer i uke 34. En detalj: sed "s/%21/=/g" gjør %21 om til =, men %21 er !. Likhetstegnet er %3D.

Promises og pilfunksjoner

Et Promise representerer resultatet av én asynkron handling. Det er enten pending (venter) eller settled, som betyr fulfilled (oppfylt) eller rejected (avvist). Med then(ok, feil) registreres funksjoner som kjøres når resultatet foreligger. catch(feil) er en kortform for then(null, feil). Kjeding av then erstatter tilbakekall nøstet inni hverandre («callback hell»).

En pilfunksjon x => uttrykk er en kortere skrivemåte for function (x) { return uttrykk }. Disse to er like:

// fetch_demo_1.html
fetch('fetch-test.txt')
  .then(function (respons) { return respons.text() })
  .then(function (kropp)   { document.querySelector('#beholder').innerHTML += kropp })

// fetch_demo_2.html
fetch('fetch-test.txt')
  .then(respons    => respons.text())
  .then(http_kropp => document.querySelector('#beholder').innerHTML += http_kropp)

fetch() returnerer et Promise for responsen. respons.text() (eller .json()) returnerer et nytt Promise for kroppen. Derfor trengs to then.

fetch_demo_3.html sender enten POST med kroppen i body, eller GET der feltene legges inn i URL-en med url.searchParams.set(). fetch-test.cgi skriver tilbake REQUEST_METHOD, QUERY_STRING og kroppen, så du ser forskjellen:

fetch(url, { method: 'POST', body: t2 })    // data i kroppen → stdin i CGI
url.searchParams.set('txt1', t1); fetch(url)  // data i URL-en → QUERY_STRING
Fallgruve: eksemplene peker til et gammelt emne

fetch_demo_3.html, opphav/ og kryssopphav/ har hardkodet https://debbie.usn.no/da-nan3000/… og web01.usn.no, som er adressene fra forløperemnet. Lokalt må du endre basis-URL-en til der du selv kjører CGI-skriptet, for eksempel busybox httpd fra uke 38.

Progressive webapplikasjoner (PWA)

En PWA er en vanlig nettside med egenskaper som gjør at den oppfører seg som en app: den kan virke offline og startes fra hjemskjermen. To deler:

  • Manifest, en JSON-fil koblet inn med <link rel="manifest" href="manifest.webmanifest">, med navn, ikon og start-URL.
  • Service worker, et skript som registreres med navigator.serviceWorker.register(). Det fungerer som en proxy mellom siden og tjeneren. Det kjører i egen tråd uten tilgang til DOM, og krever HTTPS (eller localhost).
// web-app/serviceArbeider.js
self.addEventListener('install', event =>          // ved installasjon:
  event.waitUntil(caches.open('mellomlager')         //   legg filene i hurtiglageret
    .then(cache => cache.addAll(['./index.html', './', './p1.txt' /* … */]))))
self.addEventListener('fetch', event =>            // ved hver forespørsel:
  event.respondWith(caches.match(event.request)))    //   svar fra hurtiglageret
Eksamensvekt: service workers ble bare spurt om i 2022–2023 (se eksamensoversikten). Kjenn igjen begrepene, men bruk tiden på opphav og fetch().
Fallgruve: web-app-eksempelet virker ikke som det er

manifest.webmanifest har "start_url" inni ikonobjektet. Det skal stå på toppnivå. index.html starter med <!doctype> uten html. p1.txt–p5.txt og ikon.png finnes ikke på debbie, og da feiler cache.addAll(), som avvises hvis bare én fil mangler. Lag filene selv hvis du vil prøve.

Samme opphav og CORS

To URL-er har samme opphav (origin, RFC 6454) når de har samme skjema, vert og port. Stien teller ikke:

Siden er lastet fra http://localhost:8080/db.htmlSamme opphav?
http://localhost:8080/person/olaJa, bare stien er forskjellig
http://localhost:8090/person/olaNei, annen port
https://localhost:8080/Nei, annet skjema
http://127.0.0.1:8080/Nei, annen vert (selv om det er samme maskin)

Retningslinjen om samme opphav (same-origin policy, SOP) håndheves av nettleseren. Kode fra ett opphav får ikke lese svaret på en forespørsel til et annet opphav. Det beskytter brukeren: et skript på en fremmed side kan ikke lese det din innloggede sesjon har tilgang til. SOP gjelder bare kode i nettleseren. curl og en konteiner som snakker med en annen konteiner, merker ingenting av den.

CORS (Cross-Origin Resource Sharing) er unntaket: tjeneren sier i responshodet hvilke fremmede opphav som får lov.

ResponshodeBetyr
Access-Control-Allow-Origin: http://localhost:8080Kode fra dette opphavet får lese svaret. Med credentials kan det ikke være *.
Access-Control-Allow-Credentials: trueSvaret kan leses også når forespørselen hadde med informasjonskapsler
Access-Control-Allow-Methods: PUTMetoder utover GET, HEAD og POST som er tillatt
Access-Control-Allow-Headers: Content-TypeHodefelt klienten får sende, for eksempel Content-Type: application/json

En enkel forespørsel (GET eller POST med et enkelt Content-Type som text/plain) sendes rett av gårde. Nettleseren sjekker hodet i svaret og stopper bare lesingen. Alt annet, for eksempel PUT, DELETE eller Content-Type: application/json, får først en forhåndskontroll (preflight): nettleseren sender OPTIONS og venter på et ja før den sender selve forespørselen.

Viktig poeng på eksamen: SOP stopper ikke at en enkel forespørsel når fram til tjeneren. Den stopper bare at koden leser svaret. En POST som endrer data, kan derfor ha skjedd selv om konsollen viser en CORS-feil.

credentials i fetch()

VerdiInformasjonskapsler sendes og lagres
'omit'Aldri

'include'Også mot fremmede opphav. Tjeneren må da svare med Allow-Credentials: true og et eksplisitt opphav.

Eksempelet på tvers av opphav

kryssopphav/send.html sender til tjeneste.cgi på et annet opphav. Kroppen styrer hvilke CORS-hoder tjenesten svarer med:

KallHoder i svaretKan siden lese svaret?
send('POST', '', 'same-origin')IngenNei. Forespørselen kom fram, men nettleseren skjuler svaret.
send('POST', 'orig', 'same-origin')Allow-OriginJa
send('POST', 'orig', 'include')Allow-OriginNei, Allow-Credentials mangler
send('POST', 'orig+cred', 'include')BeggeJa
send('PUT', 'orig+cred', 'include')Forhåndskontroll: OPTIONS får alle tre. Deretter PUT.Ja, etter forhåndskontrollen

opphav/login.html viser den andre siden av saken: siden laster passord.js fra en annen vert. Et skript som lastes med <script src>, kjører med sidens opphav og kan lese alt på siden, også passordfeltet. SOP beskytter ikke mot skript du selv har valgt å laste inn. Det er dette Subresource Integrity (integrity-attributtet) hjelper mot: nettleseren nekter å kjøre fila hvis innholdet ikke har den oppgitte hashen. Se uke 39.

Fallgruve: feil i notatene og eksemplene
  • var o["navn"] = 'pål' er en syntaksfeil. var deklarerer variabler og kan ikke stå foran et medlem. Skriv o["navn"] = 'pål'.
  • catch (err): err er det som ble kastet, som regel et Error-objekt med .message, ikke en tekststreng.
  • En anonym function (x) {…} alene på en linje er en syntaksfeil. Den må tilordnes eller sendes som argument.
  • system.log(this) skal være console.log(this).
  • I ajax-send.html står h.load = … og respons.text(). Det skal være h.onload og h.responseText. Dessuten gjøres strengen 'false' om til true når den tilordnes withCredentials, så alle «false»-variantene sender likevel med informasjonskapsler.

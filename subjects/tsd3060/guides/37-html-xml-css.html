Semistrukturerte data

Mye data har ikke den faste tabellstrukturen en relasjonsdatabase krever, men har likevel en viss struktur. Slike data kalles semistrukturerte. De kan

  • være irregulære og ufullstendige,
  • ha en struktur som endres ofte,
  • være skjemaløse, med bare begrensninger på selve dataene.

JSON og XML er typiske eksempler. Skjemaet bygges ofte når dataene leses inn, i stedet for å være definert på forhånd som i en relasjonsdatabase. Spørringer mot slike data er som regel navigerende (du går gjennom en trestruktur og finner data etter posisjon) og ikke deklarative som SQL.

SGML (Standard Generalized Markup Language, ISO-standard fra 1986) er en tidlig standard for å definere slike oppmerkingsspråk. Den skiller struktur fra data, lar brukeren definere strukturen selv med en DTD, og er idégrunnlaget for både HTML og XML. Den høye kompleksiteten bremset utbredelsen.

Dokumentet som tre

Et dokument med et tekstavsnitt og en nummerert liste med to punkter er et tre: dokumentet er roten, avsnittet og lista er barn, og hvert punkt er barn av lista. Samme tre kan skrives i HTML eller XML:

<!doctype html>
<html>
  <head></head>
  <body>
    <p>Tekstavsnitt</p>
    <ol>
      <li>første punkt</li>
      <li>andre punkt</li>
    </ol>
  </body>
</html>
<?xml version="1.0"?>
<dokument>
  <avsnitt>tekstavsnitt</avsnitt>
  <nummerert_liste>
    <punkt>første punkt</punkt>
    <punkt>andre punkt</punkt>
  </nummerert_liste>
</dokument>

Forskjellen: i HTML er elementnavnene faste og har kjent betydning (ol er en nummerert liste). I XML finner du på navnene selv, og de sier ingenting om hvordan dokumentet skal vises.

HTML

HyperText Markup Language er oppmerkingsspråket for webdokumenter, utviklet av Tim Berners-Lee og andre på CERN, med plattformuavhengighet som mål: det skulle virke på ulike PC-er og PDA-er, og i dag på telefoner, TV-er, biler og kjøleskap.

ÅrHendelse
1991Første liste over HTML-tagger
1995Standardisert av IETF (RFC 1866), basert på SGML
2014HTML5 fra W3C. I dag vedlikeholdes standarden av WHATWG som en «levende standard»

HTML5 erstatter HTML 4.01 og er ikke lenger basert på SGML. Standarden prøver å gjøre tilleggsmoduler (plugins) overflødige og inkluderer:

  • DOM (Document Object Model) med API for JavaScript,
  • egne elementer for lyd, video og tegning (audio, video, canvas),
  • semantiske elementer (section, article, header, nav),
  • støtte for SVG (vektorgrafikk) og MathML (matematisk notasjon).

HTML-spesifikasjonen deler elementene inn i seks typer:

Et minimalt, gyldig HTML5-dokument:

<!doctype html>
<html lang="no">
  <head>
    <meta charset="utf-8">
    <title>Tittel</title>
  </head>
  <body>
    <h1>Overskrift</h1>
    <p>Vanlig tekst i et avsnitt. Linjeskift må kodes med <br>.
       Vi kan referere til andre URL-er med <i>hyperlenker</i>:</p>
    <a href="http://www.usn.no" id="123">Hyperlenke</a>
  </body>
</html>

XML

eXtensible Markup Language er laget for å representere semistrukturerte data. Et XML-dokument består av elementer. Et element har en start-tagg, en slutt-tagg og innholdet mellom dem, som kan være andre elementer, tekst og entitetsreferanser (for tegn som ikke finnes på tastaturet, reserverte tegn som &lt;, og «snarveier» til tekst eller eksterne filer). Elementer kan også ha attributter.

Et XML-dokument er velformet (well-formed) når

  1. ett rotelement inneholder alle de andre elementene,
  2. elementene er nøstet i en trestruktur uten overlapping (<a><b></a></b> er ulovlig),
  3. alle ikke-tomme elementer har både start- og slutt-tagg.

XML 1.0 bør ha en XML-deklarasjon først (<?xml version="1.0"?>). XML 1.1 må ha den.

Mange API-er svarer med XML. Eksempel fra Posten:

URL="https://adressesok.posten.no/api/v1/postal_codes.xml?postal_code=3112"
curl -s $URL | xq > 3112.xml

xq er ikke installert som standard. xmllint --format - gir samme pene utskrift.

Fallgruve: XML tilgir ingenting

HTML-parseren i nettleseren retter opp feil i stillhet. XML-parseren gir opp ved første feil og viser en feilmelding i stedet for dokumentet. Vanlige årsaker: en slutt-tagg som mangler, & som ikke er skrevet &amp;, og store/små bokstaver som ikke stemmer (<Bok>…</bok>). XML skiller mellom store og små bokstaver.

Navnerom

Med navnerom kan et dokument bruke elementer fra ulike kilder uten navnekollisjon. Navnerommet identifiseres med en URI (globalt unik), og får et lokalt prefiks i dokumentet. Standardnavnerommet har ikke prefiks:

<xml-eksempel
    xmlns:tekst="http://debbie.usn.no/navnerom/tekst"
    xmlns:tall="http://debbie.usn.no/navnerom/tall">
  <tekst:punkt>første punkt</tekst:punkt>
  <tekst:punkt>andre punkt</tekst:punkt>
  <tall:punkt>x=1; y=2</tall:punkt>
  <tall:punkt>x=3; y=4</tall:punkt>
</xml-eksempel>

Her er tekst:punkt og tall:punkt to forskjellige elementtyper, selv om begge heter punkt.

Gyldig XML: DTD og XML Schema

Velformet betyr at syntaksen er riktig. Gyldig (valid) betyr i tillegg at dokumentet følger en bestemt innholdsmodell: hvilke elementer som er lov, i hvilken rekkefølge og hvor mange. Innholdsmodellen beskrives med en DTD (Document Type Definition) eller et XML Schema. Ingen av dem er påkrevd.

En DTD har fire typer deklarasjoner: element, attributtliste, entitet og notasjon.

<!ELEMENT bokliste (bok+)>                    <!-- én eller flere bok -->
<!ELEMENT bok (tittel, etternavn, fornavn)>    <!-- akkurat disse, i denne rekkefølgen -->
<!ELEMENT tittel (#PCDATA)>                    <!-- tekst -->
<!ELEMENT etternavn (#PCDATA)>
<!ELEMENT fornavn (#PCDATA)>
<!ATTLIST bok id CDATA #REQUIRED>             <!-- bok må ha attributtet id -->
DTDXML Schema (W3C)
Skrevet iEgen syntaks, ikke XMLXML
NavneromIkke støttetStøttet
DatatyperSvært begrenset (i praksis bare tekst)Mange (heltall, dato, …), knyttet til hvert element

XML Schema løser altså begrensningene ved DTD. Det gir mer uttrykkskraft, og webapplikasjoner kan utveksle XML robust uten egne ad hoc-verktøy for kontroll. For en sikker webtjeneste betyr det at mottatte data kan valideres mot et skjema før de brukes.

Fallgruve: nettleseren sjekker ikke DTD-en

Nettleseren sjekker bare at dokumentet er velformet. Om det er gyldig etter DTD-en, må du sjekke selv (sudo apt install libxml2-utils):

<!DOCTYPE timeliste SYSTEM "timeliste.dtd">     <!-- i XML-fila, rett etter deklarasjonen -->

xmllint --noout --valid timeliste.xml                  # mot DTD
xmllint --noout --schema timeliste.xsd timeliste.xml   # mot XML Schema

CSS

Cascading Style Sheets bestemmer utseendet, og ble foreslått av Håkon Wium Lie fra Halden. CSS kan styre visningen av både HTML og XML, men kan ikke endre strukturen i dokumentet. Du kan prøve i nettleserkonsollet: document.body.style.backgroundColor="red".

Syntaksen er en selektor, som velger elementer i dokumentet, fulgt av navn–verdi-par:

selektor { navn: verdi; navn: verdi; ... }

Elementer kan grupperes i klasser (.navn), og enkeltelementer kan få en id (#navn):

.sitat     { color: green }
.hypotese  { color: blue }
#viktigste { color: red }

<p class="hypotese">dette blir et blått avsnitt</p>
<p class="sitat">dette blir et grønt avsnitt</p>
<p id="viktigste">dette blir rødt</p>

Noen pseudoklasser og pseudoelementer: :link, :visited, :active, ::first-line og ::first-letter.

Fire måter å bruke CSS i HTML

<!-- 1. I et style-element i head -->
<style media="screen"> p { color: gray } </style>

<!-- 2. Lenke til egen stilfil -->
<link rel="stylesheet" href="stil.css">

<!-- 3. Importere en stilfil i et stilsett -->
<style>
  @import url(http://...);
  i { color: red }
</style>

<!-- 4. Som attributt på elementet (selektoren er underforstått) -->
<i style="color: red">Dette blir kursiv og rødt</i>

CSS i XML

XML-elementer har ingen innebygd visning, så nettleseren viser bare treet. Med en xml-stylesheet-instruksjon kan en CSS-fil bestemme hvordan hvert element vises:

<?xml version="1.0"?>
<?xml-stylesheet type="text/css" href="bok1.css"?>
<bokliste>
  <bok>
    <bokid>02</bokid>
    <tittel>Notater til DA-ODA2000</tittel>
    <forfatterId>12345</forfatterId>
  </bok>
  ...
</bokliste>
/* bok1.css */
bokliste { background-color: #448888; display: table; }
bok      { display: table-row; background-color: darkgreen; text-align: center; }
bokid    { background-color: red; font-family: "Times New Roman"; font-size: 32px; }

Her gjør display om vilkårlige XML-elementer til en tabell og tabellrader. Samme idé gir en nummerert liste av punkt-elementene i navneromseksempelet:

punkt { display: list-item; list-style-position: inside; list-style-type: decimal; }

Sammenstilling

En liten nettside som lenker til eksemplene over. Alt kan serveres fra en konteiner med busybox sin httpd (se uke 36):

<!DOCTYPE html>
<html lang="no">
  <head>
    <meta charset="utf-8">
    <title>HTML-eksempel</title>
    <link rel="stylesheet" href="css-eksempel.css">
  </head>
  <body>
    <ul>
      <li><a href="html-eksempel.html">html</a></li>
      <li><a href="xml-eksempel.xml">xml</a></li>
      <li><a href="css-eksempel.css">css</a></li>
      <li><a href="bok1.xml">bok1</a></li>
    </ul>
  </body>
</html>
